# PRD — ERP 모집단 자동 추출 도구

## 배경

감사/회계 부서에서 반복되는 "모집단 추출" 업무 — 엑셀 조건으로 SAP를 조회하고, 결과를
정리하고, 담당자를 확인하고, 건수·금액을 검증하는 일 — 를 자동화한다. 회사 내 협업
자동화 도구(Cowork 등)를 쓸 수 없는 환경이라, 이 도구가 그 대체 역할을 한다.

## 목표 (우선순위 순)

업무 효율화가 최우선이며, 아래 5가지를 원칙으로 한다.

1. **여러 조회조건 일괄 처리** — 조건 엑셀의 모든 행을 한 번에 실행, 결과를 하나로 통합
2. **원클릭 전체 자동화** — 조회 → 다운로드 → 담당자매칭 → 검증 → 저장까지 추가 조작 없음
3. **거래코드(통제) 설정화** — 신규 업무 추가 시 코드 수정 없이 설정(웹 등록 폼)만으로 확장
4. **실패 건만 자동 재처리** — 부분 실패 시 전체 재실행 없이 실패 건만 재시도
5. **예외만 사람이 확인** — 정상 건은 자동 확정, 문제 있는 건만 예외 시트로 분리

## 범위

### 포함
- SAP GUI Scripting(RPA) 기반 조회 자동화 — 사용자가 로그인한 세션에 attach
- SAP 조회 3단계 흐름: ①t-code 입력·조회조건 입력·화면 캡처→실행(F8) ②조회결과 산출 후
  통제별로 명기된 특정 레이아웃 선택 ③조회결과 화면 캡처 후 SAP 자체 엑셀 다운로드
- 조회조건/결과 화면 캡처 (텍스트 로그 대체 감사 증적) — 결과 엑셀에 이미지 삽입
- 인사데이터 기반 담당자/담당부서 매칭 (사번 → 이름 → 아이디 순차 매칭)
- 건수·금액 검증, 중복 체크, 정상/예외 분류
- **표본 추출** — 통제 등록 시 명기한 주기(연간/분기/월별/주별/일별) 또는 실행 시점
  모집단 건수를 기준으로, 확정된 기준표(아래)에 따라 항상 위험도 상단(최대치)을 적용해
  표본 수를 산정하고 모집단에서 무작위 비복원추출
- 통제(업무) 등록 웹 화면 — 조회 필드매핑 + 다운로드 절차 + 레이아웃 선택 + 편집 규칙
  (컬럼정리/필터/계산컬럼) + 표본추출 기준(주기적/수시)
- 실행 웹 화면 — 세션 선택, 파일 업로드, 실행, 결과 다운로드, 실패건 재처리
- 결과 엑셀 5개 탭: 캡처 / Raw data / 모집단 data / 샘플 data / 예외 data

### 제외 (후순위 — 핵심 자동화 검증 후 진행)
- GCP 연동 (결과 아카이빙, Gemini CLI로 배포)
- 표본추출 기준표 자체가 감사 목적에 타당한지에 대한 방법론 검토 (아래 표는 사용자가
  한국회계기준원 내부회계관리제도 모범규준 적용 FAQ 34 등을 근거로 확정한 값을 그대로
  구현한 것 — 이 도구는 그 기준을 기계적으로 적용할 뿐, 기준 자체의 타당성은 검증하지 않는다)
- 보안·테스트 종합 검토

## 표본 수 산정 기준

한국회계기준원 내부회계관리제도 모범규준 적용 FAQ 34 및 주요 회계법인 감사방법론을
근거로 사용자가 확정. **위험도(고/중/저)와 무관하게 항상 범위의 상단(최대치)을 적용**하며,
산정된 표본 수가 실제 모집단 건수보다 크면 모집단 건수로 clamp한다.

**주기적 통제** (통제 등록 시 주기를 명기):
| 통제 수행 주기 | 연간 발생 횟수 | 적용 표본 수(최대치) |
|---|---|---|
| 연간 | 1회 | 1개 |
| 분기별 | 4회 | 2개 |
| 월별 | 12회 | 4개 |
| 주별 | 52회 | 10개 |
| 일별 | 250회 내외 | 40개 |

**수시/비주기적 통제** (실행 시점 모집단 건수 기준):
| 모집단 건수 | 적용 표본 수(최대치) |
|---|---|
| 1 ~ 4건 | 전수조사 |
| 5 ~ 12건 | 4개 |
| 13 ~ 52건 | 15개 |
| 53 ~ 250건 | 25개 |
| 250건 초과 | 60개 |

구현: `src/validation/sampling.py`(`determine_sample_size`, `select_sample`), 통제별 설정은
`ControlConfig.sampling`(`control_type`: periodic/event_driven, `cycle`).

## 데이터 흐름

```
조건 엑셀(여러 행) + 인사데이터 엑셀 + 통제 선택 + SAP 세션 선택
  -> [배치 순회] 조건마다:
       SAP 세션 attach -> t-code 이동 -> 화면 필드 입력 -> 조회조건 캡처
       -> 실행(F8) -> 특정 레이아웃 선택(통제별 명기, 없으면 생략) -> 조회결과 캡처
       -> SAP 엑셀 다운로드(Raw data) -> 통제별 편집 규칙 적용(컬럼정리/필터/계산컬럼)
       (조건 하나 실패해도 나머지는 계속 진행, 실패는 기록만)
  -> [결과 통합] 모든 조건의 Raw data를 하나로 병합, 캡처 이미지 삽입
  -> [담당자 매칭] 사번 -> 이름 -> 아이디 순으로 인사데이터와 매칭
  -> [검증/분류] 건수·금액 대사, 중복 체크, 담당자 미확인 판정
       -> 정상 건: 모집단 data로 자동 확정
       -> 예외 건: 예외 data로 분리 (중복 / 담당자미확인 / 조회실패 / 금액불일치)
  -> [표본 추출] 모집단 data 건수(또는 통제 주기)로 표본 수 산정 -> 무작위 비복원추출 -> 샘플 data
  -> 결과 엑셀 다운로드 (캡처 / Raw data / 모집단 data / 샘플 data / 예외 data)
```

## 사용자 시나리오

**통제 등록** (개발자 개입 없이 신규 업무 추가)
1. 웹 화면에서 거래코드, 화면 필드 매핑, 다운로드 절차, 편집 규칙, 검증 규칙 입력
2. 저장하면 `config/transactions/<control_id>.yaml` 생성

**실행**
1. SAP Logon에 로그인 (사용자가 직접 — 자동화가 자격증명을 다루지 않음)
2. 웹 화면에서 통제 선택 + SAP 세션 선택 + 조건/인사데이터 엑셀 업로드 + 실행
3. 완료 후 성공/실패 건수만 표시 (진행률 바 없음)
4. 결과 다운로드, 필요 시 실패건만 재처리

## 비기능 요구사항 / 제약

- SAP HANA DB 직접 접속·RFC 연동 불가 (보안 정책) → SAP GUI Scripting만 사용
- 실행은 사용자 PC에서 로컬로만 가능 (SAP GUI Scripting은 로그인된 Windows 세션 필요) —
  GCP는 결과 저장소 역할만, 실행 엔진이 될 수 없음
- 스크립팅 가능 여부는 트랜잭션마다 다름 (Classic Dynpro 여부) — 통제 등록 전 개별 확인 필요
- 텍스트 로그 없음 — 화면 캡처가 유일한 실행 증적

## 알려진 이슈 (2026-07-26 기준, QA에서 발견)

| 이슈 | 영향 | 상태 |
|---|---|---|
| `/api/runs`가 배치 실행을 블로킹 — 서버 전체가 멈춤 | 동시 사용/폴링 불가 | 미해결 |
| 실행 탭 버튼과 탭 이름이 둘 다 "실행" | 자동화·사용자 혼동 | 미해결 |
| `validate_totals`가 파이프라인에서 호출 안 됨 | 건수·금액 검증이 실제로 동작 안 함 | 미해결 |
| 편집규칙 필터가 문자열 비교라 숫자 필터가 틀릴 수 있음 | 잘못된 필터링 결과 | 미해결 |
| 이름으로 담당자 매칭 시 동명이인 오매칭 가능, 검증 없이 자동 확정 | 잘못된 담당자로 자동 확정 위험 | 미해결 |
| SAP 필드 id 등 입력값에 대한 안내/예시가 화면에 없음 | 비개발자가 통제 등록 불가 | 미해결 |
| 통제 등록 시 동일 ID 덮어쓰기 경고 없음 | 기존 설정 조용히 유실 가능 | 미해결 |
| 여러 사용자 동시 사용 미고려 (작업 이력이 서버 메모리에만 존재) | 다중 사용자 환경에서 불안정 | 미해결 |
| 인증/업로드 크기 제한 등 보안 검토 전무 | 로컬 전용 전제가 검증 안 됨 | 후순위(security-test-review) |
| 통제 등록 웹 화면에 레이아웃 선택/표본추출 기준 입력 필드가 없음 (API/YAML 스키마는 지원하나 UI 미반영) | 비개발자가 웹 화면만으로 레이아웃·표본기준을 등록할 수 없음 | 미해결 (ui-designer 스펙 필요) |

## 미해결 질문

- 새 통제의 SAP 화면이 Classic Dynpro인지 확인하는 절차를 누가, 언제 수행하는가?
- 건수·금액 "기대값"은 조건 엑셀에 별도 컬럼으로 받는가, 아니면 실행 후 수치만 보고하는가?
- 동일 control_id 재등록 시 덮어쓸지/버전 관리할지?
- 여러 사용자가 이 도구를 동시에 쓸 계획이 있는가? (있다면 작업 상태 저장 방식을 바꿔야 함)
- 레이아웃 선택 팝업의 정확한 컴포넌트 id(`select_button_id`/`layout_name_field_id`/
  `confirm_button_id`)는 SAP 필드 id와 마찬가지로 통제마다 실제 환경에서 GUI Scripting
  레코딩으로 확인해야 한다 — 이 확인 절차와 책임자도 위 "Classic Dynpro 확인" 질문과 동일하게
  아직 미정.

## 성공 기준

- 실제 SAP Logon 환경에서 통제 1개를 등록해 조건 엑셀을 실행하고, 결과 엑셀이 정상 생성됨
- 조건 일부를 의도적으로 실패시켰을 때, 재처리 버튼으로 실패건만 재실행되어 결과에 반영됨
- 알려진 이슈 중 "미해결" 항목이 해소됨
